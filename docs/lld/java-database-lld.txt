Design note:
DatabaseServer owns StorageEngine and NetworkModule lifecycles; uses QueryProcessor (no lifecycle).
NetworkModule owns RequestHandler.
Wire protocol v1: request frame = plain UTF-8 SQL; response frame = JSON WireResponse (see docs/protocol/wire-protocol.md). QueryProcessor returns QueryResult; DefaultRequestHandler calls result.toWireResponse() (Ok, Error, or ResultSet+Done). executeText() / toResponse() remain for tests and logging.
DefaultQueryProcessor owns QueryLexer, QueryParser, and QueryPlanner; builds DefaultQueryAnalyser and QueryDispatcher on first catalog use from StorageEngine managers (requires start()). Uses StorageEngine (does not own its lifecycle).
execute() lexes, parses, analyses, plans, then runs plans through QueryDispatcher. Implicit DDL: TransactionManager.runInTransaction → ENGINE IX → table/db locks → LockManager.runExclusiveCatalog → WAL append (txnId) → CatalogManager → COMMIT+flush. Explicit BEGIN: TransactionControlExecutor holds lock, defer catalog persist until COMMIT. CHECKPOINT: CheckpointExecutor → ENGINE X → flush WAL → bufferPool.flushAll → exclusive catalog → WALManager.checkpoint(); refused inside explicit txn or while other BEGIN sessions active. Background CheckpointScheduler plugs one CheckpointStrategy (timeout or wal_size) when CHECKPOINT_ENABLED; same ENGINE X + flushAll + fence path. DESCRIBE / SHOW DATABASES / SHOW TABLES read CatalogManager only (no txn, lock, or WAL). Table names are database.table. SELECT / INSERT / UPDATE / DELETE are analysed and planned (table vs index scan from catalog IndexMetadata); VolcanoExecutor takes ENGINE IS (SELECT) or ENGINE IX (DML) before table/row locks. SeqScan (SELECT) takes row S-lock then re-reads via TableStore.findByRowId — heap scan snapshot at open() can be stale after lock wait. UPDATE/DELETE use WriteScanPrefilter: pre-lock Filter only for WHERE id = literal; otherwise UpdateOperator/DeleteOperator lock each heap row, re-read, then evaluate WHERE (unlock X if row gone or WHERE fails and lock was taken this statement). Empty SELECT returns a result set with zero rows (executeText still "OK"). DROP TABLE/DATABASE clears store heaps via CommandExecutor. VectorizedExecutor / BatchExecutor exist as stubs but are not registered. Unresolved plans still echo OK <query>.
Lex/parse errors become the response via LexException/ParseException.toResponse() (exact 0-based index).
Lexer types live under com.example.database.processor.lexer (unchanged names).
Parser types live under com.example.database.processor.parser.
DefaultQueryParser dispatches via ParserRegistry; statement parsers own grammar; AST holds structure.
DatabaseServer passes QueryProcessor into NetworkModule; NetworkModule assigns it to RequestHandler.
RequestHandler bridges network and query processor (JSON wire responses via JsonWireResponse).
java.net.Socket classes stay inside the TCP implementations.
database-client is a separate Maven module: DatabaseClient REPL over the same length-prefixed TCP framing; parses JSON with client.wire.WireResponseJson, prints via ResponsePrinter. WalCrashHarness (load/verify) and MixedCrashHarness (multi-client load/verify/checkpoint) support test-scripts force-kill recovery checks. Not wired from Main/StorageEngine.

Catalog (Phase 1.1–1.3):
CatalogManager is a StorageEngine submodule and owns CatalogStore.
DefaultStorageEngine constructs PhysicalStorage(pageSize from ServerEnvironment), DefaultCatalogManager, DefaultWALManager, FileIndexStore(keyPadding from ServerEnvironment), DefaultUndoManager(indexStore), DefaultTransactionManager(wal, undo), DefaultLockManager (DETECT_RESOLVE), CheckpointScheduler (strategy from ServerEnvironment + BufferPool), DefaultBufferPool(frameCount from ServerEnvironment; WAL flush gate + IndexPageWal hook), IndexMaintainer (logical INDEX_* WAL), and UndoableTableStore over FileTableStore (logical row WAL + page LSN). start() runs PageFileValidator on all .ibd/.idx, then loads catalog, catalog replay, DML redo, IndexPageWal.replay, loads index key types, seeds next txnId, starts scheduler if enabled. stop() flushes dirty buffer-pool pages then stops the scheduler.
start() calls catalogManager.load() — the engine does not touch catalog files.
createTable assigns ids and writes data/<db>/<table>/catalog.json. Restart: new engine, start, getTable("shop","users").
CREATE DATABASE creates data/<name>/; DROP DATABASE removes an empty directory (fails if tables remain). load() lists those directories and per-table catalogs.
CREATE TABLE via SQL: CREATE DATABASE shop then CREATE TABLE shop.users (...); processor.execute then a new StorageEngine on the same dir; getTable is the same; a second CREATE is an error.
DROP TABLE shop.users deletes the table catalog file and empty table folder.
Root data/catalog.json is not read or written.
CatalogStore owns JSON and path layout; PhysicalStorage owns bytes.

PhysicalStorage (Phase 1.2):
PhysicalStorage is a StorageEngine submodule. DefaultPhysicalStorage is filesystem bytes under DataDirectory.
No page read/write APIs. Catalog JSON is opaque bytes at this layer.

Page layout (Phase 2):
HeapPage / RowCodec / Rid / RidMap live under storage.page. Pure codecs over byte[pageSize]; default 16 KiB.
Header (24 B) + slot directory (4 B × slotCount) + free [lower,upper) + packed row payloads from the high end.
rowId remains the lock/undo key; Rid=(pageId,slotId) is the heap address. InMemoryRidMap is RAM-only.
TableStore is FileTableStore (one .ibd per table; RidMap in RAM, rebuilt on open). BufferPool.newPage writes an empty HeapPage image when extending a file.

BufferPool (Phase 3):
DefaultBufferPool is constructed by DefaultStorageEngine; pin/unpin, per-frame S/X latch, dirty bit, clock eviction.
Page key is (file, pageId). Phase 3 never evicts dirty frames (no-steal until DML WAL); flush/flushAll write them.
stop() calls flushAll(). Catalog JSON and wal.log stay off the pool. CommandExecutor.prepareTable on CREATE TABLE; drop heap before catalog on DROP TABLE.
