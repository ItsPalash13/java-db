Relationship

DatabaseServer
      │
      ├── owns ▶ StorageEngine  → DataDirectory
      │              ├── PhysicalStorage
      │              │         └── DefaultPhysicalStorage (uses DataDirectory)
      │              ├── CatalogManager
      │              │         └── DefaultCatalogManager
      │              │               ├── CatalogStore (JsonCatalogStore, catalog.json)
      │              │               │         └── uses PhysicalStorage
      │              │               └── TableMetadata → ColumnMetadata → ColumnType
      │              └── (later) TableStore, IndexStore,
      │                  LockManager, TransactionManager, WALManager,
      │                  BufferPool
      ├── uses ▶ QueryProcessor
      │              │
      │              └── DefaultQueryProcessor coordinates
      │                        ├── owns ▶ QueryLexer  → Token (TokenCatalog)
      │                        ├── owns ▶ QueryParser (DefaultQueryParser)
      │                        ├── per query ▶ QueryAnalyser (DefaultQueryAnalyser + CatalogManager)
      │                        ├── owns ▶ QueryPlanner (DefaultQueryPlanner → CreateTablePlan / CreateDatabasePlan / DropDatabasePlan)
      │                        ├── ExecutorService → ExecutorRegistry
      │                        │         └── CREATE_TABLE / CREATE_DATABASE / DROP_DATABASE → CommandExecutor → CatalogManager (write)
      │                        │              ├── ParserRegistry → Select/Update/Insert/Delete/Create/Alter/DropParser
      │                        │              └── AstNode (Query / Expression)
      │                        └── uses ▶ StorageEngine (shared)
      └── owns ▶ NetworkModule
                    │
                    ├── creates/owns ▶ RequestHandler(queryProcessor)
                    └── ServerSocket → ClientConnection

Design note:
DatabaseServer owns StorageEngine and NetworkModule lifecycles; uses QueryProcessor (no lifecycle).
NetworkModule owns RequestHandler.
DefaultQueryProcessor owns QueryLexer, QueryParser, and QueryPlanner; builds DefaultQueryAnalyser and ExecutorService on first catalog use from StorageEngine.catalogManager() (requires start()). Uses StorageEngine (does not own its lifecycle).
execute() lexes, parses, analyses, plans, then runs CREATE TABLE / CREATE DATABASE / DROP DATABASE through ExecutorService. Unresolved plans still echo OK <query>.
Lex/parse errors become the response via LexException/ParseException.toResponse() (exact 0-based index).
Lexer types live under com.example.database.processor.lexer (unchanged names).
Parser types live under com.example.database.processor.parser.
DefaultQueryParser dispatches via ParserRegistry; statement parsers own grammar; AST holds structure.
DatabaseServer passes QueryProcessor into NetworkModule; NetworkModule assigns it to RequestHandler.
RequestHandler bridges network and query processor.
java.net.Socket classes stay inside the TCP implementations.

Catalog (Phase 1.1–1.3):
CatalogManager is a StorageEngine submodule and owns CatalogStore.
DefaultStorageEngine constructs PhysicalStorage and DefaultCatalogManager(physicalStorage).
start() calls catalogManager.load() — the engine does not touch catalog.json.
createTable assigns ids and rewrites catalog.json. Restart: new engine, start, getTable("users").
CREATE DATABASE creates data/<name>/; DROP DATABASE removes an empty directory. load() also lists those directories.
CREATE TABLE via SQL (Phase 1.8): processor.execute then a new StorageEngine on the same dir; getTable is the same; a second CREATE is an error.
CatalogStore owns JSON and database directory names; PhysicalStorage owns bytes.

PhysicalStorage (Phase 1.2):
PhysicalStorage is a StorageEngine submodule. DefaultPhysicalStorage is filesystem bytes under DataDirectory.
No page read/write APIs. Catalog JSON is opaque bytes at this layer.
