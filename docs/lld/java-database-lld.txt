Relationship

DatabaseServer
      │
      ├── owns ▶ StorageEngine  → DataDirectory
      │              └── (later) CatalogManager, TableStore, IndexStore,
      │                  LockManager, TransactionManager, WALManager,
      │                  BufferPool, PhysicalStorage
      ├── uses ▶ QueryProcessor
      │              │
      │              └── DefaultQueryProcessor coordinates
      │                        ├── owns ▶ QueryLexer  → Token (TokenCatalog)
      │                        ├── owns ▶ QueryParser (DefaultQueryParser)
      │                        │              ├── ParserRegistry → Select/Update/Insert/Delete/Create/Alter/DropParser
      │                        │              └── AstNode (Query / Expression)
      │                        └── uses ▶ StorageEngine (shared)
      └── owns ▶ NetworkModule
                    │
                    ├── creates/owns ▶ RequestHandler(queryProcessor)
                    └── ServerSocket → ClientConnection

Design note:
DatabaseServer owns StorageEngine and NetworkModule lifecycles; uses QueryProcessor (no lifecycle).
NetworkModule owns RequestHandler.
DefaultQueryProcessor owns QueryLexer and QueryParser; uses StorageEngine (does not own its lifecycle).
execute() lexes then parses then echoes.
Lex/parse errors become the response via LexException/ParseException.toResponse() (exact 0-based index).
Lexer types live under com.example.database.processor.lexer (unchanged names).
Parser types live under com.example.database.processor.parser.
DefaultQueryParser dispatches via ParserRegistry; statement parsers own grammar; AST holds structure.
DatabaseServer passes QueryProcessor into NetworkModule; NetworkModule assigns it to RequestHandler.
RequestHandler bridges network and query processor.
java.net.Socket classes stay inside the TCP implementations.
