Relationship

DatabaseServer
      │
      ├── owns ▶ StorageEngine  → DataDirectory
      │              ├── PhysicalStorage
      │              │         └── DefaultPhysicalStorage (uses DataDirectory)
      │              ├── CatalogManager
      │              │         └── DefaultCatalogManager
      │              │               ├── CatalogStore (JsonCatalogStore, db/table/catalog.json)
      │              │               │         └── uses PhysicalStorage
      │              │               └── TableMetadata → ColumnMetadata → ColumnType
      │              ├── TransactionManager → DefaultTransactionManager
      │              ├── LockManager → DefaultLockManager (catalog X + scoped db/table/row)

Design note:
DatabaseServer owns StorageEngine and NetworkModule lifecycles; uses QueryProcessor (no lifecycle).
NetworkModule owns RequestHandler.
Wire protocol v1: request frame = plain UTF-8 SQL; response frame = JSON WireResponse (see docs/protocol/wire-protocol.md). QueryProcessor returns QueryResult; DefaultRequestHandler calls result.toWireResponse() (Ok, Error, or ResultSet+Done). executeText() / toResponse() remain for tests and logging.
DefaultQueryProcessor owns QueryLexer, QueryParser, and QueryPlanner; builds DefaultQueryAnalyser and QueryDispatcher on first catalog use from StorageEngine managers (requires start()). Uses StorageEngine (does not own its lifecycle).
execute() lexes, parses, analyses, plans, then runs plans through QueryDispatcher. Implicit DDL: TransactionManager.runInTransaction → LockManager.runExclusiveCatalog → WAL append (txnId) → CatalogManager → COMMIT+flush. Explicit BEGIN: TransactionControlExecutor holds lock, defer catalog persist until COMMIT. CHECKPOINT: CheckpointExecutor → exclusive catalog → WALManager.checkpoint() (update wal.checkpoint, append CHECKPOINT to wal.log — append-only); refused inside explicit txn. Background CheckpointScheduler plugs one CheckpointStrategy (timeout or wal_size) when CHECKPOINT_ENABLED. DESCRIBE / SHOW DATABASES / SHOW TABLES read CatalogManager only (no txn, lock, or WAL). Table names are database.table. SELECT / INSERT / UPDATE / DELETE are analysed and planned (table vs index scan from catalog IndexMetadata); VolcanoExecutor compiles plans into pull operators over InMemoryTableStore (INDEX_SCAN = SeqScan until B+Tree). Empty SELECT returns a result set with zero rows (executeText still "OK"). Rows are RAM-only — restart keeps catalog, SELECT is empty. DROP TABLE/DATABASE clears store heaps via CommandExecutor. VectorizedExecutor / BatchExecutor exist as stubs but are not registered. Unresolved plans still echo OK <query>.
Lex/parse errors become the response via LexException/ParseException.toResponse() (exact 0-based index).
Lexer types live under com.example.database.processor.lexer (unchanged names).
Parser types live under com.example.database.processor.parser.
DefaultQueryParser dispatches via ParserRegistry; statement parsers own grammar; AST holds structure.
DatabaseServer passes QueryProcessor into NetworkModule; NetworkModule assigns it to RequestHandler.
RequestHandler bridges network and query processor (JSON wire responses via JsonWireResponse).
java.net.Socket classes stay inside the TCP implementations.
database-client is a separate Maven module: DatabaseClient REPL over the same length-prefixed TCP framing; parses JSON with client.wire.WireResponseJson, prints via ResponsePrinter. Not wired from Main/StorageEngine.

Catalog (Phase 1.1–1.3):
CatalogManager is a StorageEngine submodule and owns CatalogStore.
DefaultStorageEngine constructs PhysicalStorage, DefaultCatalogManager, DefaultWALManager, DefaultTransactionManager(wal), DefaultLockManager, CheckpointScheduler (strategy from ServerEnvironment), and InMemoryTableStore. start() loads catalog, replays WAL (COMMIT-gated; merges wal.checkpoint maxTxnId), seeds next txnId, starts scheduler if enabled.
start() calls catalogManager.load() — the engine does not touch catalog files.
createTable assigns ids and writes data/<db>/<table>/catalog.json. Restart: new engine, start, getTable("shop","users").
CREATE DATABASE creates data/<name>/; DROP DATABASE removes an empty directory (fails if tables remain). load() lists those directories and per-table catalogs.
CREATE TABLE via SQL: CREATE DATABASE shop then CREATE TABLE shop.users (...); processor.execute then a new StorageEngine on the same dir; getTable is the same; a second CREATE is an error.
DROP TABLE shop.users deletes the table catalog file and empty table folder.
Root data/catalog.json is not read or written.
CatalogStore owns JSON and path layout; PhysicalStorage owns bytes.

PhysicalStorage (Phase 1.2):
PhysicalStorage is a StorageEngine submodule. DefaultPhysicalStorage is filesystem bytes under DataDirectory.
No page read/write APIs. Catalog JSON is opaque bytes at this layer.
